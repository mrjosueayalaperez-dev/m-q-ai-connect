## 010a: bookings ISO dates + favicon

- `POST /api/bookings` `local_start` now accepts ISO 8601:
  - `YYYY-MM-DD`: 00:00 local time in `tz`. This is a judgment call: a date with no time starts at midnight.
  - `YYYY-MM-DD HH:MM` (the old form, unchanged) or `YYYY-MM-DDTHH:MM[:SS[.ffffff]]`: local time in `tz`.
  - A trailing `Z` or a `±HH:MM` / `±HHMM` offset: that exact instant. `tz` is still recorded for display and reminders.
- Storage is unchanged: `starts_at_utc` stays `YYYY-MM-DDTHH:MM:SSZ`, and fractions of a second are dropped.
- Malformed input returns **400** with a clear message, never 500:
  - empty or blank: "local_start is required — …";
  - garbage: "local_start must be an ISO date or date-time, e.g. …";
  - impossible date or time (e.g. 2027-02-30, 24:00): "… not a real calendar date or time …";
  - unknown timezone.
- An unknown `customer_id` is now 404 "customer not found". It used to be a 500 from the foreign key.
- Before (0a0ba5e): the 'T' form, garbage, empty and 2027-02-30 all returned 500.
- Roles are unchanged: viewer gets 403, anonymous (even with X-Role) gets 401.
- Favicon: `web/favicon.ico` (16 + 32 px, generated locally) and `web/favicon.svg`, linked in `index.html`.
  - Both are served by the existing static mount, so `/favicon.ico` is no longer a 404.
  - No CDN is involved, and the static mount is not under `/api`, so no auth change.
- Tests: `tests/test_batch10a.py`, 42 tests.
